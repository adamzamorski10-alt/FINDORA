## 1. Financial Rules

### 1.1 Transaction Definition

**Income vs Expense vs Transfer**
- `type` field is `'income'` or `'expense'`. No explicit `'transfer'` type exists.
- Transfers are simulated by creating paired transactions: an expense from one place and an income to another, both with `_transfer: true` (though this flag is inconsistently applied).
- Source: `index.html:20529` (transaction form), `src/domain/income/income-profile-balance-calculator.js:27`

**MUST PRESERVE**: The `type` field must remain a simple `'income'|'expense'` enum. Transfer simulation via paired transactions is legacy behavior.

### 1.2 Amount Handling

- Amounts are `number` type, parsed with `parseFloat()`.
- Zero amounts are allowed but filtered in some contexts (e.g., `applyAutoSaveRules` skips `saveAmt <= 0`).
- Negative amounts are permitted and propagate through calculations.
- Fractional amounts (e.g., 99.99) are preserved in JavaScript floating-point arithmetic.
- No rounding to 2 decimals at persistence boundary (except `_stripUndefinedDeep` which preserves numeric precision).
- Source: `tests/safe-to-spend-calculator.test.js:125-147`, `tests/resale-balance-calculator.test.js:183-192`

**SHOULD PRESERVE**: Raw JS number arithmetic. Financial rounding is not applied globally.

### 1.3 Currency

- All amounts are in PLN (Polish Złoty). No currency conversion logic exists.
- Display formatting uses `fmt()` which adds thousand separators and `,` decimal separator.
- Source: `index.html` (fmt function usage throughout)

**LEGACY**: No multi-currency support. Assumes single currency.

## 2. Balance Rules

### 2.1 Current Balance Calculation

```javascript
// index.html:4646-4650
function getBalances() {
  const b = { konto:0, skarbonka:0, gielda:0 };
  transactions.forEach(t => {
    if (t._excluded || !t.place) return;
    const s = t.type === 'income' ? 1 : -1;
    b[t.place] += s * t.amount;
  });
  return b;
}
```

**Rules**:
- Only three places are tracked: `konto`, `skarbonka`, `gielda`.
- Transactions with `_excluded: true` are ignored.
- Transactions with `place: null` or `place: undefined` are ignored.
- Transactions with unknown `place` (not in `{konto, skarbonka, gielda}`) are silently ignored (no error).
- `_transfer` flag does NOT exclude from balance calculation.
- `_autoSave` flag does NOT exclude from balance calculation.
- Source: `index.html:4646-4650`, `tests/balances-as-of-characterization.test.js:27-35`, `tests/balances-as-of-characterization.test.js:141-153`

**MUST PRESERVE**: Silent ignore of unknown places. This prevents crashes from stale data.

### 2.2 Historical Balance (As-Of)

```javascript
// tests/balances-as-of-characterization.test.js:27-35
function legacyGetBalancesAsOf(dateStr, transactions) {
  const b = { konto:0, skarbonka:0 };
  (transactions || []).forEach(t => {
    if (t._excluded || !t.place || !t.date || t.date > dateStr) return;
    if (b[t.place] === undefined) return;
    b[t.place] += (t.type === 'income' ? 1 : -1) * t.amount;
  });
  return b;
}
```

**Rules**:
- Same exclusion rules as current balance.
- Additionally excludes transactions with `date > dateStr` (lexicographic comparison).
- Missing dates are excluded.
- Only `konto` and `skarbonka` are tracked (NOT `gielda`).
- Source: `src/domain/balances/balances-as-of-calculator.js`, `tests/balances-as-of-characterization.test.js`

**LEGACY_BEHAVIOR**: `gielda` is excluded from historical balances. This may be intentional (gielda is virtual) or an oversight.

### 2.3 Resale Internal Wallet

```javascript
// src/domain/resale/resale-balance-calculator.js:15-28
function compute(inputs) {
  const sourceId = inputs.sourceId;
  const transactions = inputs.transactions || [];
  const held = transactions
    .filter(t => t._sourceId === sourceId && t._resaleBalance && t.type === 'income')
    .reduce((s, t) => s + t.amount, 0);
  const spent = transactions
    .filter(t => t._sourceId === sourceId && (t._resaleWithdraw || t._resalePaidFromBalance) && t.type === 'expense')
    .reduce((s, t) => s + t.amount, 0);
  return Math.max(0, held - spent);
}
```

**Rules**:
- Per-source wallet (not global).
- Only transactions matching `_sourceId` are counted.
- `held` = sum of income transactions with `_resaleBalance: true`.
- `spent` = sum of expense transactions with `_resaleWithdraw: true` OR `_resalePaidFromBalance: true`.
- Result is clamped to `>= 0` (cannot go negative).
- Negative amounts in held/spent are summed as-is (can reduce balance).
- Source: `src/domain/resale/resale-balance-calculator.js`, `tests/resale-balance-calculator.test.js:162-181`

**MUST PRESERVE**: `Math.max(0, held - spent)` clamp. Prevents negative wallet balance.

### 2.4 Gielda Balance

```javascript
// index.html:4688-4694
function getGieldaBalance() {
  const dep = gieldaOps.filter(o=>o.type==='wplata').reduce((s,o)=>s+o.amount,0);
  const wit = gieldaOps.filter(o=>o.type==='wyplata').reduce((s,o)=>s+o.amount,0);
  const ear = gieldaOps.filter(o=>o.type==='zarobek').reduce((s,o)=>s+o.amount,0);
  const los = gieldaOps.filter(o=>o.type==='strata').reduce((s,o)=>s+o.amount,0);
  return dep - wit + ear - los;
}
```

**Rules**:
- Computed from `gieldaOps` only (not transactions).
- Formula: deposits - withdrawals + earnings - losses.
- No `asOf` date filtering in the legacy function (but `GieldaBalanceCalculator` supports it).
- Source: `index.html:4688-4694`, `src/domain/gielda/gielda-balance-calculator.js`

**MUST PRESERVE**: The formula `dep - wit + ear - los`. This is the core gielda accounting rule.

### 2.5 Income Profile Balance

```javascript
// src/domain/income/income-profile-balance-calculator.js:13-31
function compute(inputs) {
  const profile = inputs.profile;
  const transactions = inputs.transactions;
  const gieldaBalance = inputs.gieldaBalance;
  if (!profile) return 0;
  if (profile.id === 'gielda') return gieldaBalance;
  const base = Number(profile.balance) || 0;
  const txNet = (transactions || [])
    .filter(t => t._sourceId === profile.id && !t._transfer)

}
```

**Rules**:
- `gielda` profile delegates to `gieldaBalance`.
- Other profiles: `base + txNet`, where `base = profile.balance` (persisted default + manual edits).
- Transfers (`_transfer`) are excluded from the net.
- `_excluded` transactions are NOT excluded here (unlike balance calculations).
- Source: `src/domain/income/income-profile-balance-calculator.js`, `tests/income-profile-balance-characterization.test.js`

**REVIEW**: `_excluded` transactions ARE included in profile balance. This may be intentional (internal transfers) or a bug.

## 4. Safe-to-Spend Rules

### 4.1 Formula

**G1.3 update**: Safe-to-Spend was simplified for MVP-1 greenfield. `bills` is deferred to MVP-2, and the return shape is narrowed to `{ safeTotal, perDay }`.

```javascript
// Frozen greenfield contract (G1.1/G1.2/G1.3)
function computeSafeToSpend(freeFunds, goalsReq, daysLeft) {
  const clampedDays = Math.max(1, daysLeft);
  const safeTotal = freeFunds - goalsReq;
  const perDay = safeTotal / clampedDays;
  return { safeTotal, perDay };
}
```

**Frozen contract**:
- Input: `{ freeFunds, goalsReq, daysLeft }`
- Output: `{ safeTotal, perDay }`
- `safeTotal = freeFunds - goalsReq` (no bills component in MVP-1)
- `daysLeft` is clamped to `>= 1` inside the calculator
- `perDay` is always finite
- **MUST PRESERVE**: This frozen greenfield contract. The legacy `bills` component and full return shape are no longer part of the active formula.

### 4.2 Days Left

```javascript
// index.html:4703-4707
function getDaysLeftInMonth() {
  const now = new Date();
  const lastDay = new Date(now.getFullYear(), now.getMonth() + 1, 0).getDate();
  return lastDay - now.getDate() + 1;
}
```

**Rules**:
- Inclusive: if today is the last day, returns 1.
- Uses local time (not UTC).
- Source: `tests/safe-to-spend-characterization.test.js:34-36`

### 4.3 Upcoming Bills


- Each occurrence adds `r.amount` (not the actual transaction amount).
- Source: `index.html:4711-4718`, `tests/safe-to-spend-characterization.test.js:172-200`

### 4.4 Required Goal Deposits

```javascript
// index.html:4723-4737
function getRequiredGoalDepositsThisMonth() {
  const now = new Date();
  let total = 0;
  goals.forEach(g => {
    const remaining = (g.target || 0) - (g.current || 0);
    if (remaining <= 0 || !g.deadline) return;
    const deadline = new Date(g.deadline);
    if (deadline < now) { total += remaining; return; }
    let monthsLeft = (deadline.getFullYear() - now.getFullYear()) * 12
                    + (deadline.getMonth() - now.getMonth()) + 1;
    monthsLeft = Math.max(1, monthsLeft);
    total += remaining / monthsLeft;
  });
  return total;
}
```

**Rules**:
- Only goals with `deadline` and `remaining > 0`.
- Past deadline: entire remaining amount is urgent (added in full).
- Future deadline: `remaining / monthsLeft` (minimum 1 month).
- Months left calculation: `(deadlineYear - nowYear) * 12 + (deadlineMonth - nowMonth) + 1`.
- Source: `tests/safe-to-spend-characterization.test.js:202-231`

### 4.5 Edge Cases

| Case | Behavior |
|---|---|
| `daysLeft = 0` | `perDay = Infinity` (division by zero) |
| `safeTotal < 0` | `perDay` is negative |
| No goals | `goalsReq = 0` |
| No bills | `bills = 0` |
| Goal already reached | Skipped |
| Goal without deadline | Skipped |
| Fractional days/amounts | Raw JS arithmetic, no rounding |

**REVIEW**: `Infinity` perDay when `daysLeft = 0` is displayed directly in UI. May cause rendering issues.

### 5.2 ETA Calculation

```javascript
// tests/goal-eta-characterization.test.js:26-45
function legacyGoalEtaInfo(g, transactions) {
  const remaining = g.target - g.current;
  if (remaining <= 0) return null;
  const goalTx = transactions.filter(t => t._goalId === g.id && t.type === 'expense' && !t._excluded);
  if (goalTx.length === 0) return { unknown: true };
  const dates = goalTx.map(t => new Date(t.date)).sort((a, b) => a - b);
  const first = dates[0];
  const now = new Date();
  const monthsSpan = Math.max(1, (now.getFullYear() - first.getFullYear()) * 12 + (now.getMonth() - first.getMonth()) + 1);
  const totalSaved = goalTx.reduce((s, t) => s + t.amount, 0);
  const avgPerMonth = totalSaved / monthsSpan;
  if (avgPerMonth <= 0) return { unknown: true };
  const monthsNeeded = Math.ceil(remaining / avgPerMonth);
  const etaDate = new Date(now.getFullYear(), now.getMonth() + monthsNeeded, 1);
  return { monthsNeeded, avgPerMonth, etaDate, unknown: false };
}
```

**Rules**:
- Uses transactions with `_goalId === g.id`, `type === 'expense'`, `!t._excluded`.
- `monthsSpan` = calendar months from first deposit to now (minimum 1).
- `avgPerMonth` = totalSaved / monthsSpan.
- If `avgPerMonth <= 0`, returns `{ unknown: true }`.
- `monthsNeeded = Math.ceil(remaining / avgPerMonth)`.
- `etaDate` = first day of month `now + monthsNeeded`.
- Source: `tests/goal-eta-characterization.test.js`, `src/domain/goals/goal-eta-calculator.js`

**MUST PRESERVE**: The ETA formula and the `unknown` fallback.

- Source: `tests/characterization.test.js:275`, `index.html:17825-17829`

### 7.3 Debt Repayment

### 7.4 Debts As-Of


## 8. Recurring & Auto-Save Rules

### 8.1 Recurring Rule Model


### 8.2 Next Date Calculation

```javascript
// src/domain/recurring/recurring-next-date-calculator.js:10-29
function compute(inputs) {
  const rule = inputs.rule;
  if (!rule.lastBooked) return rule.startDate;
  const last = new Date(rule.lastBooked);
  let next = new Date(last);
  if (rule.freq === 'weekly') {
    next.setDate(next.getDate() + 7);
  } else if (rule.freq === 'yearly') {
    next.setFullYear(next.getFullYear() + 1);
  } else {
    next.setMonth(next.getMonth() + 1);
    const maxDay = new Date(next.getFullYear(), next.getMonth() + 1, 0).getDate();
    next.setDate(Math.min(rule.dayOfMonth || 1, maxDay));
  }
  return next.toISOString().split('T')[0];
}
```

**Rules**:
- If `lastBooked` is null/undefined, returns `startDate`.
- Weekly: +7 days from `lastBooked`.
- Yearly: +1 year from `lastBooked`.
- Monthly: +1 month, then clamp `dayOfMonth` to max days in that month.
- `dayOfMonth` defaults to 1 if missing.
- Source: `src/domain/recurring/recurring-next-date-calculator.js`

**MUST PRESERVE**: The day clamping for monthly rules (e.g., Jan 31 -> Feb 28/29).

### 8.3 Is Due

```javascript

  const threshold = thresholdEl ? parseInt(thresholdEl.value) : 50;
  // Build 3-month average per category

    const pastTx = getMonthTransactions(offset - i).filter(t => t.type==='expense' && !t._transfer && !t._autoSave);
```

## 18. LEGACY

These behaviors should NOT be automatically carried forward to the new Finora:

1. **Global state architecture**: All state on `window.*`. Should move to proper state management.
2. **Transaction as flat schema with underscore flags**: Should be normalized into proper entity relationships.
3. **Paired transfer transactions**: Should use explicit transfer entity.
4. **`_stripUndefinedDeep` persistence boundary**: Inconsistent `undefined` vs empty string vs `null`.
5. **`uid()` collision-prone generator**: `Date.now().toString(36) + random`. Should use UUID v4.
6. **`RESALE_EVENTS_MAX = 5000` hard cap**: No archiving strategy.
7. **Inline base64 label storage**: `_labelData` in resaleSales. Should use external storage.
8. **`gielda` as money place**: Virtual place mixed with real accounts.
9. **`incomeSources` + `incomeProfiles` dual model**: Should be unified.
10. **Guest mode with debtor link**: Complex sharing mechanism (`guestDebtorRef`, `guestCanEdit`).
11. **`ruleTargets` hardcoded defaults**: 50/30/20 not enforced, just displayed.
12. **`isSubscription` flag on recurring**: Not used meaningfully.
13. **Vinted price tracker**: Separate localStorage-based feature (`_vintedPrices`, `_vintedMeta`).
