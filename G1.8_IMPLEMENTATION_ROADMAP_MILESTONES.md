## 6. RISK REGISTER

| Risk | Probability | Impact | Mitigation |
|------|-----------|--------|-----------|
| Data loss during migration | LOW | HIGH | Atomic migrations, preserve original, dry-run tests |
| Performance regression | MEDIUM | MEDIUM | Profile before/after, lazy loading for large lists |
| User data incompatible with new schema | LOW | HIGH | Backward-compatible migrations, version detection |
| Test flakiness | MEDIUM | LOW | Deterministic tests, mock time/dates |
| Scope creep | MEDIUM | HIGH | Strict phase gates, MVP-first approach |
| Legacy breakage during UI migration | MEDIUM | HIGH | Incremental migration, parallel testing |

---

## 7. ROLLBACK PLAN

If a phase fails:

1. **Repositories fail**: Revert to DataLayer-only. Repositories can be added later.
2. **Services fail**: Services are additive; UI can fall back to direct DataLayer calls.
3. **UI migration fails**: Revert index.html to last known good state. Components already extracted can be reused.
4. **Migration fails**: Data preserved in original format. Migration can be retried.

## Summary

G1.8 defines the complete greenfield implementation roadmap: 4 phases, ~10 weeks, 9 repositories, 8 services, 9 views, with clear milestones and success criteria.

**Key principles**:
- Incremental: one repository/service/view at a time.
- Backward compatible: legacy code works during migration.
- Test-driven: every module has unit tests before integration.
- Local-first: IndexedDB primary, Firebase optional sync.

**Total estimated effort**: ~10 weeks (1 developer).
