## 1. PURPOSE

G1.3 defines the **exact public API contract** for every module in the greenfield architecture. This is the "interface layer" between design and implementation.

Each contract includes:
- Function signature
- Input schema
- Output schema
- Side-effect rules
- Error behavior
- Dependencies

---

## 2. DOMAIN CALCULATORS

All calculators are **pure functions**. They receive explicit inputs and return deterministic outputs. They must not:
- Read global state
- Access the DOM
- Call persistence
- Throw errors for invalid input (return `null` or `undefined` for missing optional fields)

### 2.1 SafeToSpendCalculator

```javascript
compute(inputs) → {
  freeFunds: number,     // available cash across all active accounts
  bills: number,         // upcoming bills this month
  goalsReq: number,      // required goal deposits this month
  daysLeft: number       // days remaining in current month
} → {
  daysLeft: number,
  freeFunds: number,
  bills: number,
  goalsReq: number,
  safeTotal: number,     // freeFunds - bills - goalsReq
  perDay: number         // safeTotal / daysLeft (NaN if daysLeft === 0)
}
```

**Rules**:
- `safeTotal` can be negative (user is over-committed).
- `perDay` is `NaN` when `daysLeft === 0` (last day of month).
- All input defaults to `0`.

**Status**: Implemented in `src/domain/safe-to-spend/safe-to-spend-calculator.js`

### 2.2 AccountBalancesCalculator

```javascript
compute(inputs) → {
  accounts: Account[],
  transactions: Transaction[]
} → {
  balances: Record<string, number>,  // accountId → balance
  total: number                      // sum of all non-archived account balances
}
```

**Rules**:
- Balance = sum of all transactions for account (income - expense).
- Transfers are counted as income in target account, expense in source.
- Archived accounts are excluded from `total` but included in `balances`.

### 2.10 GoalEtaCalculator


## 4. REPOSITORIES

Repositories own CRUD for a single domain entity. They know about StorageAdapter but nothing about Firebase, DOM, or domain calculators.

### 4.1 TransactionRepository

```javascript
class TransactionRepository {
  constructor(storageAdapter, userId)

  // Read
  loadAll() → Promise<Transaction[]>
  findById(id) → Promise<Transaction | null>
  findByMonth(monthKey) → Promise<Transaction[]>
  findByAccount(accountId) → Promise<Transaction[]>
  findByCategory(categoryId, monthKey) → Promise<Transaction[]>

  // Write
  save(transaction) → Promise<void>
  saveMany(transactions) → Promise<void>
  remove(id) → Promise<void>

  // Listen
  listen(callback) → { unsubscribe: () => void }
}
```

**Storage key**: `finapp_transactions`

## 6. ENTITY SCHEMAS

### 6.1 Account

```javascript
{
  id: string,              // UUID v4
  userId: string,
  name: string,
  type: 'cash' | 'bank' | 'savings' | 'investment',
  icon: string,
  color: string,
  archived: boolean,
  createdAt: string,       // ISO date-time
  updatedAt: string        // ISO date-time
}
```

**Validation**:
- `id` required, non-empty
- `type` required, one of allowed values
- `name` required, non-empty
- `archived` defaults to `false`

---

### 6.2 Category

```javascript
{
  id: string,
  userId: string,
  name: string,
  type: 'income' | 'expense',
  icon: string,
  color: string,
  parentId: string | null,
  isSystem: boolean,
  createdAt: string,
  updatedAt: string
}
```

**Validation**:
- `id` required
- `type` required
- System categories cannot be deleted.

---

### 6.3 Transaction

```javascript
{
  id: string,
  userId: string,
  accountId: string,
  amount: number,           // always positive; sign determined by type
  type: 'income' | 'expense' | 'transfer',
  categoryId: string | null,
  description: string,
  date: string,             // YYYY-MM-DD
  tags: string[],
  notes: string,
  metadata: Record<string, any>,
  createdAt: string,
  updatedAt: string
}
```

**Validation**:
- `amount` must be > 0.
- `type` required.
- `accountId` required.
- `date` required, format YYYY-MM-DD.
- `tags` always array (never undefined).
- `notes` always string (never undefined).
- `metadata` always object (never undefined).

**Transfer linkage**: When `type === 'transfer'`, `metadata.transferId` links to paired transaction.

## 8. ERROR HANDLING

### 8.1 Calculator Errors

Calculators must not throw. They return `null` or `undefined` for invalid input.

```javascript
// Example
function compute(inputs) {
  if (!inputs) return null;
  if (inputs.daysLeft <= 0) return { perDay: NaN, ... };
  // ...
}
```

### 8.2 Service Errors

Services may throw for missing calculators:
```javascript
if (!window.SafeToSpendCalculator) {
  throw new Error('SafeToSpendCalculator not available');
}
```

### 8.3 Repository Errors

Repositories propagate StorageAdapter errors:
```javascript
try {
  await this.storage.set(key, data);
} catch (err) {
  throw new Error(`Failed to save ${this.entityName}: ${err.message}`);
}
```

### 8.4 Validation Errors

Repositories validate before save:
```javascript
save(entity) {
  const errors = validateEntity(entity, this.entitySchema);
  if (errors.length > 0) {
    throw new ValidationError(errors);
  }
  // ...
}
```
